hermes-mobile: same chats on every device

Approved plan · issues on GitHub · details in PLAN.md and issues.md (33 issues)

The goal

Use Hermes like Telegram: open the Android tablet and see the same chats, group rooms and bot-to-bot threads as on Desktop, live. Read something on one device and it's read everywhere. Pick up a conversation in the middle, even a room that is running right now. Desktop doesn't need to be running.

A milestone is done when the automated checks pass on the box and you've ticked a short checklist on your tablet (about 5 minutes).

Protocol contracts (G0)

New gateway calls are written down before anyone codes them. A stock gateway stays usable: each call is behind a flag on groups.capabilities, and the app keeps polling when the flag is absent. Lead sign-off is still open.

ContractFlagAdds
groups.eventevent_pushA hint that a room changed (room_id, latest seq, kind, authority epoch). The client fetches the new rows. Not a second copy of the message.
groups.readread_cursorsOne read marker per room, shared by every device. groups.list / groups.state gain read_seq and unread_count.
Device resumedevice_cursorsA random device id and a per-device “where I was” cursor. Not the read marker. No hardware ids.
Bridgemethod present or absentMobile implements the existing preparedSubmissions journal, plus an optional deviceIdentity().

Full text: planning/contracts/. The room hint uses the same event envelope as sessions.changed. Its epoch is the room’s authority epoch, which survives a restart; it is not the in-memory session replay epoch.

No due dates. We start now and go as fast as the checks allow, one milestone after another. Until upstream merges, pavillion-claw runs our patched branch.

Team and review

Hermes Mobile (lead): splits the work, reviews every change hard, writes your checklists. Writes no code.

Eng A: the app, Android, and the automated browser tests.

Eng B: gateway changes, the patched branch, upstream PRs.

  1. Contracts first: new gateway calls are written down and approved before coding.
  2. Every PR: one issue, tests, no secrets, lead review.
  3. Every milestone: automated checks at phone and tablet sizes, then your 5-minute tablet checklist.
  4. Upstream PRs: from basilrari, opened only after you approve the title and body.
  5. Real replies in tests: DeepSeek Flash, capped at $5 a month.

Main risks

  • Upstream is slow to merge. Patches stay small and switchable; the app still works without them by polling.
  • Upstream changes daily. We resync at the start of each milestone.
  • Two room drivers on pavillion-claw (dashboard and the Telegram gateway share one home). The doctor and a restart test check it.
  • Android kills background apps. Send journal and reconnect logic. With no push, nothing arrives while the app is closed; it catches up when you open it.
  • Browser tests miss device bugs. Your checklist covers those.

Your decisions

  1. You run a 5-minute tablet checklist per milestone; everything else is automated on the box. No phone testing, no adb.
  2. Patched gateway branch is fine; you approve each upstream PR.
  3. No push notifications.
  4. Read once, read everywhere.
  5. One machine (pavillion-claw); Telegram stays separate; no second gateway.
  6. No old rooms to migrate.
  7. Durable replay buffer stays optional.
  8. DeepSeek Flash, $5/month for tests.
  9. App ID io.github.basilrari.hermesmobile, one reinstall.
  10. HTTPS only via tailscale serve.
  11. Android only.

Not in this plan

iOS · push notifications · app stores and release signing · secrets in any commit · a second gateway · Telegram sync · fixing Desktop's relay · a new chat UI.
